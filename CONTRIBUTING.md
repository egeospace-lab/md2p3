# Contributing to md2p3

## Introduction

Contributions are what make **md2p3** such an inspiring place to learn, collaborate, and create. Any contributions you make are greatly appreciated. We welcome patches, improvements, and ideas from our stakeholders.

Before contributing, please discuss the change you wish to make via an issue, email, or other communication channel with the maintainers of this repository.

Contact: [md2p3@egeospace.in](mailto:md2p3@egeospace.in)

## Why Read This Guide

Following these guidelines demonstrates respect for the time and effort of the developers managing this project. In return, maintainers will reciprocate by addressing your issue, assessing changes, and helping you finalise your pull requests.

### Ways of Contributing

There are many ways to contribute, including:

- Writing tutorials or blog posts
- Improving documentation
- Submitting bug reports and feature requests
- Writing code that can be incorporated into **md2p3** itself

### What Is Not Considered a Contribution

While collaboration is welcome, the following are **not** considered contributions within the scope of this project:

- Support questions
- Feature suggestions that target only a small group or reflect personal preferences
- Biased opinions promoting products, ideas, or agendas unrelated to the project

## Code of Conduct

### Our Pledge
We pledge to foster an open and welcoming environment, making participation in our project and community a harassment‑free experience for everyone.

### Our Standards
**Positive behaviours include:**
- Using welcoming and inclusive language
- Respecting differing viewpoints and experiences
- Accepting constructive criticism gracefully
- Focusing on what benefits the community
- Showing empathy towards other members

**Unacceptable behaviours include:**
- Trolling, insulting, or derogatory comments
- Harassment (public or private)
- Publishing private information without consent
- Conduct inappropriate in a professional setting

### Responsibilities
Project maintainers are responsible for clarifying standards and taking corrective action when necessary. They may remove or reject contributions not aligned with this Code of Conduct, or ban contributors for inappropriate behaviour.

### Scope
This Code of Conduct applies within project spaces and in public spaces when representing the project or its community.

### Enforcement
Instances of unacceptable behaviour may be reported to [md2p3@egeospace.in](mailto:md2p3@egeospace.in). Complaints will be reviewed confidentially and addressed appropriately.

## Getting Started

### New Contributors
We recommend newcomers explore documentation, blog posts, issues, and feature discussions to quickly get onboard. Issues marked as beginner‑friendly are a great place to start.

Remember: everyone starts as a beginner — feel free to ask for help!

### Contributor Licence Agreement (CLA)
All contributions must be accompanied by a CLA. By signing, you (or your employer) agree to transfer copyright of your contribution to **EGEOSPACE (PRIVATE) LIMITED**.

Visit [eGeoSpace](https://www.egeospace.in/) to check your agreements or sign a new one. You generally only need to submit a CLA once.

### Small or "Obvious" Fixes
Minor contributions (e.g., spelling corrections, formatting changes, metadata updates) may be submitted without a CLA. Examples include:
- Grammar or typo fixes
- White space and formatting changes
- Comment clean‑up
- Bug fixes that adjust constants or return values
- Logging/debugging improvements
- Updates to `.gitignore` or build scripts
- Moving files between directories

### Major Contributions
For larger changes:
1. Fork the repository
2. Implement your changes in the fork
3. Ensure compliance with project code style and Code of Conduct
4. Sign the CLA with **EGEOSPACE (PRIVATE) LIMITED**
5. Submit a pull request indicating your CLA status

## Reporting Bugs

### Security Disclosure
If you find a security vulnerability, **do not open an issue**. Email [md2p3@egeospace.in](mailto:md2p3@egeospace.in) directly.

### Filing a Bug
When filing a bug, please include:
1. Project version
2. Operating system and architecture
3. What you did
4. What you expected
5. What you saw instead

## Suggesting Features

If you’d like a new feature:
- Describe the feature clearly
- Explain why you need it
- Suggest how it should work

Our engineers will review and discuss feasibility.

## Code Reviews

All submissions, including those by project members, require review via pull requests.

You can connect with the developers at [eGeoSpace](https://www.egeospace.in/).

For code style, commit messages, tags, and labelling conventions, please refer to [eGeoSpace](https://www.egeospace.in/).
